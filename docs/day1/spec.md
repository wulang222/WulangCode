# 多协议 LLM 终端对话客户端 Spec

## 背景
mewcode 是一个从零构建的、Claude Code 风格的终端 AI Agent。本项目是其第一块基石：
在没有工具调用、权限、记忆等高级能力之前，先打通"人 ↔ LLM"的最小闭环——
让用户能在终端里与大模型进行流畅的多轮对话。

## 目标
- 打通 LLM API 调用：能向大模型发起请求并正确接收回复。
- 同时支持 Anthropic 与 OpenAI 两种协议，通过同一份配置切换接入对象（含兼容端点）。
- 提供一个全功能终端界面（TUI），承载启动横幅、输入、流式输出、状态栏。
- 回复以流式方式实时呈现，结束后以 markdown 形式美化展示。
- 在单次会话内维护完整对话上下文，支持连续多轮交流。
- 对调用失败有可恢复的错误反馈，不中断会话。

## 功能需求

- F1: 配置加载
  从 YAML 配置读取一个 providers 列表（可含多项）。每项包含：可读名称、协议类型、
  可选的自定义端点地址、密钥、模型名、是否开启扩展思考。配置支持用户全局、项目级、
  本地覆盖三层来源，后层覆盖前层，便于在不影响共享配置的前提下做本地调试。逐项校验
  必要项，缺失或非法时给出清晰的启动期错误并终止，而非崩溃堆栈。

- F2: 密钥来源回退
  若条目未显式提供密钥，按协议从对应的环境变量读取。两处都缺失时给出明确的鉴权错误
  提示。密钥仅用于发起请求，不在界面回显、不写入对话区、不写入会话相关的持久化输出。

- F3: provider 选择
  若配置中仅有一个 provider，直接采用它进入对话；若有多个，启动后先呈现一个选择
  界面（方向键列表，列出每项的名称、协议与模型），用户选定一项后再进入对话。被
  选定者即本次会话的活动 provider。

- F4: 多协议适配
  根据活动 provider 的协议类型选择对应的请求构造与响应解析方式，统一支持 Anthropic
  与 OpenAI 两种协议；其中 OpenAI 协议可使用其官方端点，亦可通过自定义端点地址接入
  各类兼容服务（如代理、第三方推理平台等）。对上层暴露与协议无关的统一对话接口。

- F5: 发起对话请求
  将"内置系统提示词 + 当前完整对话历史"作为上下文，向活动 provider 发起一次对话
  请求，并按配置决定是否开启扩展思考。内置系统提示词应反映当前运行环境（如工作目录
  等），让模型对会话上下文有基本认知。

- F6: 流式接收
  以流式方式接收回复，实时解析出正文文本增量并向界面输送。对扩展思考产生的思考
  增量正确识别但不渲染（接收即丢弃），不得混入正文。

- F7: 多轮上下文
  在单次会话内维护完整对话历史（用户与助手消息交替追加）。每一轮新请求都携带此前
  全部上下文，实现连续多轮对话。程序退出后历史不保留。

- F8: 终端界面布局
  启动后呈现一个全功能终端界面，自上而下包含：
  (a) 启动横幅：ASCII 猫咪图案 + 应用名与版本号 + 当前模型 + 当前工作目录；
  (b) 历史对话区：依时间顺序展示历次用户输入与助手回复；
  (c) 流式期间的进行中指示：带动画、随机动词与实时秒数；
  (d) 底部带边框的输入框，含提示符与占位文字，并有空闲/聚焦/错误等可识别状态；
  (e) 底部状态栏：显示活动 provider 信息与基本计数。

- F9: 流式呈现与渲染
  助手回复在流式期间以纯文本逐字实时显示；该轮回复结束后，将其整段以 markdown
  形式重新渲染美化（代码块、列表、强调等）后定型展示，并与历史区其他消息一同保留。

- F10: 输入与提交
  用户在输入框键入文本，可用约定的键位插入换行进行多行编辑；按 Enter 提交。提交后
  清空输入框，界面进入等待/流式状态，该状态下不接受新的提交，直至本轮回复结束。
  可通过方向键回放此前提交过的输入。

- F11: 退出
  提供明确的退出方式：输入 /exit 命令，或按 Ctrl+C，均可安全退出程序；退出时正确
  还原终端状态（光标可见、不残留 raw mode 等）。

- F12: 错误反馈
  当请求失败（鉴权失败、限流、网络中断、上下文超长、模型不存在等）时，在对话区以
  可区分的样式（如红字）展示错误信息，程序不退出，用户可继续下一轮对话。流式被中途
  打断时，把已经收到的部分文本作为本轮助手消息保留，便于后续追问。

- F13: 响应计时与进行中指示
  自请求发出（开始等待模型）即启动计时，以"进行中"指示实时显示已用秒数
  （形如 "Imagining… (5s)"，秒数随时间递增）；收到首个增量后继续计时；本轮回复
  结束后定型显示一次完成短语（替换掉进行中指示）。

## 非功能需求

- N1: 界面不阻塞
  网络请求与界面渲染互不阻塞。流式数据以异步方式驱动界面更新，等待与流式期间界面
  始终保持响应（可滚动、可见进行中指示），不得冻结。

- N2: 流式实时性与等待反馈
  在收到首个文本增量前，显示带动画与实时秒数的"处理中"指示，让用户明确知道正在
  等待模型；文本增量到达后尽快逐字呈现，给用户"实时打字"的观感，不做额外缓冲。

- N3: 跨协议一致体验
  无论使用 Anthropic 还是 OpenAI 协议（含自定义端点），用户感知的输入、流式输出、
  多轮上下文与错误反馈行为保持一致；上层界面只感知统一的对话事件，不感知协议差异。

- N4: 配置健壮性
  配置文件缺失、格式错误、必要字段缺失或非法等情况，给出明确可读的错误提示，而非
  崩溃堆栈。多层配置合并行为可预测：后层覆盖前层，缺失层不报错。

- N5: 密钥安全
  API 密钥不在界面回显，不打印到对话区、状态栏、进行中指示或任何会话持久化输出中。

- N6: 终端兼容与自适应
  在常见终端下正常显示；markdown 渲染与界面布局对终端宽度自适应，窄屏不错版。

- N7: 退出整洁
  退出时恢复终端状态（光标可见、原始输入模式还原等），不残留损坏的终端环境。

## 不做的事

- 工具调用 / function calling：本期不发送工具定义、不处理工具调用，纯文本对话。
- MCP 集成：本期不连接任何 MCP 服务。
- 权限系统：无任何需授权的操作，故不做权限确认。
- 上下文压缩：历史增长不做摘要/截断，超长由用户自行控制（留给后续章节）。
- 长期记忆 / 跨会话记忆：不做。
- 会话持久化恢复：历史不落盘用于续聊，重启后从空白开始。
- slash 命令体系：除 /exit 外，不做可扩展的命令系统（如 /help、/clear、/model 等）。
- 运行时切换 provider / model：多份配置仅在启动时选一次，会话中途不切换。
- 扩展思考内容展示：思考增量接收即丢弃，不渲染、不折叠展示。
- 流式中断后自动重发：仅保留已收到的部分文本，不做重试 / 退避。
- 用量统计与计费：不显示费用（但保留响应耗时计时，见 F13）。
- 多模态：不支持图片等非文本输入。

## 验收标准

- AC1: (F1/N4) 仅一份合法 provider 配置时，启动直接进入对话；字段缺失或非法时打印
  清晰错误信息并以非零状态退出，无崩溃堆栈。
- AC2: (F2) 删掉条目的密钥字段且未设环境变量时，启动构造客户端阶段给出明确的鉴权
  错误提示；密钥在任何用户可见的区域均不出现。
- AC3: (F1/N4) 同时存在用户级、项目级、本地三层配置时，后层正确覆盖前层；任一层
  缺失不影响其余层加载。
- AC4: (F3) 多份 provider 配置时，启动后出现方向键列表供选择；选定后进入对话，
  状态栏与启动横幅展示所选 provider 的名称与模型。
- AC5: (F4) 同一组对话分别用 Anthropic 协议与 OpenAI 协议（含自定义端点）配置运行，
  均能正常收发；切换配置不改变上层交互行为。
- AC6: (F5) 发出的请求包含内置系统提示词与完整历史；当配置开启扩展思考时，请求按
  该协议正确开启扩展思考。
- AC7: (F6) 回复以逐字流式出现；开启扩展思考时，界面不出现任何思考文本，仅显示最终
  回复。
- AC8: (F7) 连续多轮对话中模型能引用前文（如先告知信息、后追问，回答正确），证明
  上下文被携带；重新启动后历史为空。
- AC9: (F8) 启动界面包含：猫咪 banner + 应用名与版本 + 当前模型 + 工作目录 + 输入框
  + 底部状态栏。
- AC10: (F9) 回复结束后整段以 markdown 美化显示，代码块、列表、强调等正确渲染，并
  与此前消息一并保留在历史区。
- AC11: (F10) 输入框可换行编辑多行内容，Enter 提交，提交后输入框清空；可用方向键
  回放此前提交过的输入。
- AC12: (F11) 输入 /exit 或按 Ctrl+C 均能安全退出，退出后终端恢复正常（光标可见、
  无 raw mode 残留）。
- AC13: (F12) 用错误密钥或不存在的模型触发失败时，错误在对话区以可区分样式显示，
  程序不退出，用户可继续下一轮；流式中途断开时，已收到的部分文本被保留为助手消息。
- AC14: (F13) 从发出请求即开始计时并实时显示秒数，首个增量到达前即可见；本轮结束
  后显示完成短语并清掉进行中指示。
- AC15: (N1) 等待与流式期间，界面保持可响应（可滚动、不冻结）。
