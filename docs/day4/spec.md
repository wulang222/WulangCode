# 系统提示工程化 Spec## 背景ch04 给 MewCode 装上了 Agent Loop——能自主多轮想 → 调工具 → 看结果地干活。但「**干活的指令**」还很原始:系统提示是一段揉在一起的固定常量(身份、工具用法、简洁性挤在同一块文本里),没有结构、没有优先级、想加一类新指令只能往字符串里塞;每轮请求都把整段系统提示与全部工具定义**原样重发**,稳定不变的内容反复计费、反复占用首字延迟;模型对**当前环境**(工作目录、平台、日期、git 状态)一无所知;规划模式提醒每轮无差别地拼在系统提示尾部,注入频率不可控。

ch05 给 MewCode 做**系统提示工程化**:把全局指令拆成按职责划分、按优先级拼装的模块;把稳定内容与变化内容分到**可缓存通道**与**消息通道**,让稳定的指令和工具定义走缓存省钱省首字延迟;引入一种带特殊标签的**补充消息注入**机制,在运行中注入指令而不污染缓存、不被模型当成用户提问来回复;会话级开关(规划模式)的提醒按**轮次频率**注入。这是从「能干活」到「干得好」的一步。

## 目标

- 把全局指令拆成按职责划分的若干模块,按优先级拼装成完整系统提示;新增一类指令只需挂载新模块,不改装配逻辑。
- 区分稳定与变化内容:稳定的系统模块与工具定义跨轮逐字节一致,走**可缓存通道**;环境信息与对话历史走**不缓存的通道**。
- 在工具描述与系统提示中,对关键约定(优先用专用工具、编辑前必先读)**双重强化**,提高遵守率。
- 提供一种带特殊标签的**补充消息注入**机制:运行中注入补充指令,既不污染缓存,也不会被模型当成用户输入来回复。
- 会话级开关(规划模式)的提醒按轮次注入:**首轮完整、间隔轮次重复完整、其余轮次精简**,控制注入频率。
- 能从大模型返回中**解析缓存命中信息**(写入 / 读取 token),用于验证缓存策略真实生效。

## 功能需求

- F1: 模块化系统提示拼装
  把全局指令按职责拆成模块,每个模块带名称、优先级、内容。装配时按优先级从高到低拼接成完整系统提示,模块间以空行分隔。固定模块按优先级排:**身份 → 系统约束 → 任务模式 → 动作执行 → 工具使用 → 语气风格 → 文本输出 → 环境信息**。其后预留三个可选模块位置:**已激活 Skill、自定义指令、长期记忆**——本章这三个**不接入真实内容来源**(留待后续章节),装配时内容为空则跳过、不留多余空行。新增一类指令只需定义新模块挂到对应优先级,不改装配主逻辑。

- F2: 环境信息构造与呈现
  收集运行环境信息(工作目录、操作系统/平台、架构、Shell、是否 Git 仓库、Git 分支、当前模型、当前日期等),构造成一段供模型感知环境的文本。环境信息作为系统提示的独立段落呈现,按行罗列各项;非 Git 仓库或某项取不到时,对应行自动省略而非留空。

- F3: 稳定内容走可缓存通道
  稳定不变的内容(拼装好的系统模块 + 工具定义 + 历史前缀)归入**可缓存通道**,变化内容(每轮新增的补充消息、本轮新工具结果)归入**不缓存通道**。可缓存内容必须**跨轮逐字节一致**(不含任何随轮次变化的成分),否则缓存无法命中。对支持显式缓存标记的协议,主动在稳定前缀、工具定义末尾、历史末条用户消息尾部打缓存断点,形成多层可复用前缀;对仅靠端点前缀缓存的协议,把稳定内容置于请求前缀位置,自动受益,不强制端点支持。

- F4: 缓存命中解析
  从大模型响应用量中解析缓存字段——**缓存写入**(首次创建缓存的 token)与**缓存读取**(命中复用的 token),随用量一并对外暴露,供烟囱/调试程序打印验证缓存是否真生效。不同协议字段名不同,各自解析;字段缺失时按零处理,且为避免与原始输入 token 双计,在仅暴露命中 token 的协议路径下从输入 token 中扣除已命中部分。

- F5: 关键约定双重强化
  对模型最易违反的关键约定(如「有专用工具时绝不用通用命令拼凑」「编辑文件前必先读取」),在**工具描述**与**系统提示模块**两处都明确表述。通用命令工具的描述里列出常见误用与对应的专用工具替代关系;文件编辑工具的描述里强制「编辑前必先读」并在违反时直接失败。

- F6: 补充消息注入机制(system-reminder)
  提供一种带特殊标签(形如 `<system-reminder>`)的补充消息注入形式:构造请求时把补充指令注入**消息通道**,以用户角色追加到历史尾部,但用标签语义让模型理解这是系统补充上下文而非用户提问——不针对它直接回复。此类消息**每轮动态构造、不写入持久历史**,因而不污染缓存、不破坏历史角色交替。机制对多类提醒通用:规划模式提醒、已激活 Skill 提醒、外部钩子/通知,以及长期记忆注入,都通过同一通道下发。

- F7: 规划模式按轮次注入
  规划模式提醒改由 F6 机制承载(不再拼到系统提示尾部)。按 Agent Loop 轮次控制注入**频率与详略**:**首轮注入完整提醒(完整工作流 + 计划文件信息),之后每隔固定轮次重复一次完整提醒,其余轮次注入精简版**(仅提示规划模式仍生效、只读工具范围、收尾方式)。模式跨轮保持,`/plan` 进入、`/do` 退出并触发按计划执行;进入与退出本身也通过补充消息通道告知模型;规划模式下仍仅放开只读工具(均沿用 ch04)。

- F8: 跨协议一致
  各支持协议(Anthropic、OpenAI 及其兼容端点)都装配同一套模块化系统提示 + 环境信息、都注入相同补充消息、都尽力走缓存。两协议在模块内容、注入时机、规划模式注入节奏上**行为一致**;缓存命中解析在各自字段可得时生效,字段缺失时按零处理。

## 非功能需求- N1: 缓存确定性——可缓存块(工具定义 + 稳定系统模块 + 历史前缀)在跨轮、会话内多轮之间**逐字节稳定**:模块装配顺序固定、工具顺序固定、缓存断点仅作用于元数据标记不改变文本内容,不混入任何随轮次/时间变化的成分。否则缓存永不命中,本章核心目标落空。
- N2: 不破坏 ch04 行为——Agent Loop 多轮编排、流式双路收集、保序分批并发、用户取消、历史一致、上下文溢出与限流自恢复、自动压缩、用量/迭代进度展示等 ch04 能力**不退化**。系统提示重构与消息注入是叠加,不改这些既有路径的语义。
- N3: 历史合法性——每轮动态注入的补充消息(不持久)拼进请求后,消息序列仍**角色交替合法、工具调用与结果配对不破坏**,不致请求返回 400;连续同角色消息按协议要求自动合并;补充消息不写入持久历史,故不影响后续轮次与可恢复性。
- N4: 环境采集不阻塞、可降级——环境信息采集(含可能外调 shell 的 git 状态)**快速且有界**,不阻塞界面、不显著拖慢请求发起;任一项取不到时降级(留空/省略),不中断会话。
- N5: 密钥与敏感信息不泄漏——沿用 ch03/ch04,对话区与任何输出均不出现 api_key;环境信息构造**不带入密钥或敏感环境变量**,仅读必要的 Shell 标识等无敏感字段。
- N6: 缓存字段解析健壮——大模型或兼容端点未返回缓存字段时按零处理,不抛错、不因缺字段中断本轮或会话。
- N7: 代码规范——遵循项目 CLAUDE.md 中关于格式化、类型检查、模块组织的统一约定。
- N8: 可扩展性——新增一类系统提示模块或一类补充消息提醒时,改动局部:不触及装配主逻辑,不改协议适配层对外签名的语义稳定性。

## 不做的事- **项目指令文件加载**——「自定义指令」为预留空槽,本章不从项目级指令文件读取内容(留待后续章节)。
- **自动记忆 / 长期记忆作为系统提示模块**——「长期记忆」槽位预留,本章长期记忆即便接入也只走补充消息通道注入,不进系统提示模块,且不做记忆写入与召回。
- **真实 MCP 接入**——「已激活 Skill」为预留空槽,不接入真实 MCP 工具/资源。
- **自动化评估 / 评测框架**——本章只做缓存字段解析验证 + 一组典型场景人工对比的定性评估,不建评测流水线。
- **历史增量缓存**——只缓存稳定前缀(工具定义 + 稳定系统模块 + 历史尾部一处断点),不对中间历史另设断点。
- **缓存 TTL / 断点数配置化**——TTL 用默认值、断点位置内置,本章不通过配置调整。
- **状态栏展示缓存命中**——缓存信息只走 smoke / 调试输出,不进 TUI 状态栏。
- **提示词运行时热加载 / 外部模板文件**——模块内容内置于代码,不做外部模板。
- **多模态、流式工具结果**——沿用 ch04,不做。

## 验收标准

- AC1: 模块化装配——系统提示由按优先级排列的固定模块拼成,模块间以空行分隔;新增一个模块只需挂载、不改装配逻辑。(F1)
- AC2: 可选空槽——「已激活 Skill / 自定义指令 / 长期记忆」内容为空时装配自动跳过、不留多余空行;架构支持后续填充。(F1)
- AC3: 环境信息呈现——系统提示尾部含独立环境段,行项含工作目录、平台、Shell、是否 Git 仓库、日期;Git 仓库下额外含分支行,模型非空时含模型行。(F2)
- AC4: 缓存命中——同一会话连发两条消息:首轮缓存写入 token > 0、次轮缓存读取 token > 0,证明稳定前缀被复用;仅环境信息/历史变化时稳定前缀仍命中。(F3/N1)
- AC5: 缓存确定性——两次构造的稳定块逐字节相等;故意改变环境信息不改变稳定块内容。(F3/N1)
- AC6: 缓存字段解析——用量对外暴露缓存写/读两字段;各协议在自家字段可得时填充,缺失时为 0 且不报错。(F4/N6)
- AC7: 双重强化——关键约定(优先用专用工具、编辑前必先读)在**工具描述**与**系统提示模块**文本中均出现,且文件编辑工具在未读取的情况下直接失败。(F5)
- AC8: 补充消息注入——注入消息以 `<system-reminder>` 标签包裹,模型不把它当用户提问来复述/回应;该消息**不写入持久对话历史**。(F6/N3)
- AC9: 规划模式按轮次注入——`/plan` 后:首轮注入完整提醒、之后每隔固定轮次重复完整、其余轮次注入精简版;规划模式仅放开只读工具;`/do` 切回全工具并按上文计划执行;进入与退出本身均通过补充消息通道告知。(F7)
- AC10: 跨协议一致——各支持协议都装配同一系统提示 + 环境信息、注入同一补充消息、都尽力缓存,行为一致;缓存字段在各自可得时填充。(F8)
- AC11: 不破坏 ch04——ch04 关键行为(多轮连环、用户取消、历史一致、流出错恢复、自动压缩)仍成立;现有测试通过。(N2)
- AC12: 历史合法——注入补充消息后请求不返回 400;规划模式多轮 + 中途取消后再发一条仍可继续(历史配对合法)。(N3)
- AC13: 环境采集降级——在非 git 目录或 git 不可用时,环境段对应项降级(留空/省略),界面不卡、请求正常发起。(N4)
- AC14: 代码规范——遵循项目格式化与类型检查约定;对话区与输出无 api_key 明文;环境采集不读取除必要 Shell 标识之外的敏感环境变量。(N5/N7)
